# Engram ↔ project memory bridge

**Engram = find / prioritize / praxis scars.**  
**This tree = durable, greppable project truth.**

## How agents should use both

1. `session_start` (Engram MCP) — always first when Engram is connected.
2. Read Engram concepts below (or `helper:session_handoff_latest`).
3. Open `SCRATCH/memory/CURRENT.md` for the one-screen state.
4. Dive into topic files / SCRATCH long-form only as needed.
5. After edits: Engram `batch_remember` / update handoff **and** bump CURRENT.md if open work changed.

## Anti-patterns

- Treating Engram as a substitute for updating CURRENT.md (Engram alone can be thin at wake).
- Treating this tree as a second Engram (no need to re-encode every line).
- Writing full auto_loop transcripts into memory files.
